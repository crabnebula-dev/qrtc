Testing and CI

Unit tests run two engines against each other in one process. Interop tests put qrtc against Chromium and OpenSSL. The full browser, SFU and Matrix matrix runs in tauri-plugin-webrtc, where a real page drives the engine.

Interop tests

Chromium

cargo build --example stdio_peer
cd tests && npm ci && npx playwright-core install chromium && cd ..
node tests/chromium-interop.mjs

Headless Chromium and the stdio_peer example open data channels both ways. Each case also checks the DTLS group each side agreed:

OpenSSL

node tests/pq-tls-interop.mjs pq-moduletto
node tests/pq-tls-interop.mjs pq-hybrid

The engine's TURN over TLS client connects to an OpenSSL 3.5 server (Node's TLS) that accepts only X25519MLKEM768.

CI

.github/workflows/ci.yml runs on every push and pull request, and weekly. Actions are pinned by commit.

Releases

.github/workflows/release.yml runs on a v* tag. It checks that the tag matches the crate version, runs the tests, and builds the SBOM, the source archive and SHA-256 sums. It attests build provenance for them and attaches them to a GitHub release. Tags and commits are signed.

Consumer tests

tauri-plugin-webrtc runs qrtc inside WebKitGTK against Chromium, LiveKit with end-to-end encryption, matrix-js-sdk voice and video calls, and coturn over UDP, TCP and TLS. Its testing page lists those suites.
